# 微信与企业微信文件归档 MVP 决策

## 结论

新功能采用独立 `file-archive` 模块接入现有 Chrome MV3 侧边栏，文件监听、复制、哈希校验和后台任务由 Native Helper 完成。第一阶段不读取聊天正文、不保存账号凭据、不注入或修改微信/企业微信进程。

## 当前支持

- macOS 微信：检测 `~/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/<account>/msg/file/` 下的已完成下载目录。
- macOS 企业微信：检测已知容器和 Application Support 目录下名称明确的 `file`、`files`、`download`、`downloads`、`filemsg` 目录。
- 文件完成判断：文件大小大于 0，连续稳定等待后再处理。
- 归档：默认复制到 `导出目录/微信或企业微信/来源未知待确认/YYYY-MM-DD/`，不移动或删除源文件。
- 去重：来源应用、文件名、大小和 SHA-256 组成记录键；复制后回读目标大小和 SHA-256。
- 状态：后台守护进程将任务状态、计数、最近文件和错误写入 `~/.tianyuan-workbench/native-helper/`。

## 明确边界

仅凭下载目录路径不能可靠判断文件来自哪个联系人或群聊。当前 UI 会显示第二阶段限制，未知来源不会自动归档到指定群；后续需要找到稳定的本地消息元数据或官方接口后，才允许增加会话选择和群绑定。

## 安全取舍

- 输出目录不能位于监听源目录内，避免监听器重复处理自己的导出文件。
- 默认不读取聊天正文，不写入 Cookie、Authorization、密码、验证码、token 或微信登录状态。
- 文件名只在本地状态 UI 中展示；日志和项目记录不保存用户目录的完整敏感路径。
- OneDrive/iCloud 目录只提示同步风险，不阻止用户选择；推荐本机项目归档目录。

## 后续阶段

在不使用进程注入、不修改客户端包、不自动发送消息的前提下，先验证是否存在稳定的会话 ID、文件消息元数据或官方本地接口，再实现会话列表、多选、群绑定和高置信度自动归档。无法达到高置信度时继续保持来源未知待确认模式。
