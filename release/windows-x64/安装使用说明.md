# 天源工作台 Windows 安装说明

版本 0.14.34，正式构建 2026102705。支持 Windows 10/11 x64、Chrome 或 Edge。

## 从旧版升级

Windows 0.14.32 和 0.14.33 的旧更新器无法正确识别解压成功结果。请先下载并运行本版完整安装包一次；完成后即可使用工作台内更新功能。重复点击旧版更新按钮不会安装此修复。

## 完整安装

1. 先核对 ZIP 的 SHA-256，再将整个包解压到准备长期保留的可见目录，例如 `E:\天源工作台\TianyuanWorkbench`。不要从 ZIP 预览窗口运行。
2. 双击 `install.cmd`。安装根目录直接回车默认采用当前解压目录；也可输入其他本机目录。Agent 使用 `install-agent.cmd` 或 `install.cmd /Agent`。
3. 安装器同步并校验 Node.js、Python 及全部业务依赖、Native Helper、Native Messaging、Connector 和 Codex 插件缓存，不会只复制浏览器扩展。
4. 安装完成后，在 Chrome 的 `chrome://extensions/` 或 Edge 的 `edge://extensions/` 开启开发者模式，手动选择“加载已解压的扩展程序”，加载报告 `paths.extension` 指向的文件夹。

默认加载位置为 `<安装根目录>\extension`，例如 `E:\天源工作台\TianyuanWorkbench\extension`。生成运行文件位于同一根下的 `workbench-runtime`，不再强制把扩展复制到 C 盘 AppData 隐藏目录。用户主动指定的目录会生效，目录不可用时停止安装，不静默换目录。

Python 依赖包括 requests 及其传递依赖、openpyxl、et_xmlfile、lxml、python-docx 和 typing_extensions，安装器会检查实际采用的解释器能否导入这些组件。

解压目录就是默认运行位置，请长期保留；移动、重命名或删除会影响运行。迁移时将完整包解压到新位置后重新安装，并在浏览器重新选择实际的 extension 目录。不能从压缩包内部加载扩展。

扩展固定 ID：`lkflndcnklpeaejohaacoaolnmhgigoc`。桌面“天源工作台-浏览器扩展”入口（`天源工作台-浏览器扩展.lnk`）和文档中的 `天源工作台\浏览器扩展路径.txt` 会记录真实路径；桌面/文档可能由 OneDrive 重定向。

## 天源 CLI 单独安装

天源 CLI 为可选外部组件。完整包和轻量包均不包含 CLI 安装器，不下载、不安装或修复 CLI，也不卸载已装 CLI。已有 CLI 只进行只读可用性探测。

未检测到可运行的 CLI 时，安装器和工作台“连接配置”显示中文提示。请通过天源官方渠道单独安装或修复 CLI，安装后重启浏览器并点击“启动/检查”；需要 CLI 导出时，再由用户本人完成授权。缺少 CLI 只限制 CLI 相关导出，不阻断目录选择、打印及工作台核心组件安装。

## 结果与预检

安装报告位于 `<安装根目录>\安装检查结果.json` 和 `<安装根目录>\安装检查结果.txt`。核对真实加载位置、版本、buildNumber、runtimeBuildId、核心组件和 Connector 健康状态。

`status=success`、`allComponentsReady=true`、`readinessScope=required-components-only` 表示必需组件通过；CLI 单列在 `optionalDependencies.cli`，`required=false`、`status=unavailable` 可以与核心安装成功同时出现。核心组件失败必须返回失败和非零退出码。

可设置 `TIANYUAN_PREFLIGHT_ONLY=1` 后运行 `install-agent.cmd`，或执行 `install.ps1 -Agent -PreflightOnly`。生成的“预检结果.json”中 `installed=false` 仅代表包/依赖预检，不能算安装成功；正式安装前清除该变量。

控制台标准输出采用 UTF-8，自动化调用方应按 UTF-8 解码。Windows PowerShell 5.1 重定向日志时应显式选择 UTF-8；优先以机器可读 JSON 报告判断结果，不把 GBK 错读日志当成产品功能失败。

## 轻量更新

轻量包由 VERSION.txt 自动识别，只更新已有完整环境，不含 Node、便携 Python、CLI 安装器和 native_host.exe。从当前工作台触发更新会沿用已确认的实际安装根；旧布局仅用于兼容更新，不作为新装默认目录。

手动更新可明确指定刚才的完整安装根：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Agent -InstallRoot 'E:\天源工作台\TianyuanWorkbench'
```

无法确定原安装根或核心运行环境不完整时，轻量安装在修改服务和注册前停止，提示使用完整包。CLI 缺失不构成轻量更新失败条件。

## 实机测试与卸载

完整安装仍会处理共享 Connector、HKCU Chrome/Edge Native Messaging、用户级插件及 Codex 缓存，并可能替换桌面/文档入口。自定义 InstallRoot 不等于隔离。验收请使用干净 VM 或可回滚专用测试机；不要覆盖正在使用的正式安装。

双击本次安装目录中的 `uninstall.cmd`。卸载器只接受当前包有匹配运行配置的根，或用户显式指定且经过配置核对的根；新解压但未安装的包会提示“此目录未安装，未删除”。清理前核对当前目标的注册和进程归属，不按端口停止其他安装。扩展源码和用户文件保留，浏览器里的扩展由用户手动移除；共享缓存、系统 Python 和天源 CLI 不卸载。

仅由用户本人输入 MCP token、账号、密码和验证码。首次业务验证使用工作副本，不能在正式底稿执行上传、保存或清理。代码和包内校验不能代替完整安装、浏览器加载、目录选择回显与持久化的实机验收。
