# 天源工作台 Mac 安装说明

版本 0.14.33，正式构建 2026102703。支持 macOS 11+、Apple Silicon 和 Google Chrome；不适用于 Intel Mac。本包完成 Windows 主机交叉组包和静态完整性检查，macOS 实机运行尚未覆盖。

## 安装和加载

1. 先核对 ZIP 的 SHA-256，再完整解压到准备长期保留的可见目录，例如“下载/TianyuanWorkbench”。不要从压缩包预览中运行。
2. 双击根目录“安装.command”。完整包包含独立 Node 22.23.4、Python 安装组件和表格依赖，不借用天源 CLI 的 Node。缺少适用 Python 时，系统 Python 安装可能要求用户本人输入管理员密码。
3. 默认安装根为当前解压目录，浏览器加载其中的 `extension` 文件夹；生成运行组件放在 `workbench-runtime`。安装器不再默认把扩展复制到 `~/.tianyuan-workbench` 隐藏目录。
4. 安装结束后，在 Chrome 的 `chrome://extensions/` 开启开发者模式，手动点击“加载未打包的扩展程序”，选择报告 `paths.extension` 对应的真实目录。

扩展固定 ID：`lkflndcnklpeaejohaacoaolnmhgigoc`。解压目录就是默认运行位置，请保留完整目录；移动或删除后需重新安装并重新加载扩展。用户也可先把整个包移到自己选择的位置，再运行安装入口。

需要指定其他安装根时，可在终端显式设置 `TIANYUAN_INSTALL_ROOT`，再运行该包的“安装.command”。目标不可写时停止，不回退到隐藏目录。

## CLI 是可选组件

完整包和轻量包都不包含、下载或执行天源 CLI 安装器。已装 CLI 只做有超时的可用性检查；缺失或不可运行时显示中文安装/修复指引，不阻断工作台核心安装。

需要 CLI 相关导出时，请用户从天源官方渠道单独安装或修复 CLI，重启浏览器后点击“启动/检查”，再自行完成授权。无需在 CLI 尚未安装时先登录授权；目录选择、打印等其他功能可继续使用。

## 报告和更新

安装根目录的“安装检查结果.json”记录版本、构建号、runtimeBuildId、实际 extension/Helper/Node/Python 路径及核心检查。核心成功要求 `status=success` 和 `allComponentsReady=true`；`readinessScope=required-components-only` 表示就绪范围是必需组件。可选 CLI 由 `optionalDependencies.cli` 单独记录，`required=false`、`unavailable` 不代表核心安装失败。

轻量包自动识别为更新包，复用已经安装的受管 Node 和 Python。请从当前工作台触发更新，或显式设置当前 `TIANYUAN_INSTALL_ROOT`。找不到明确目标或必要运行环境时提示使用完整包；不会另建隐藏根或把下载暂存目录当作新安装。旧隐藏布局只保留兼容更新能力。

完整安装会修改用户级 Native Messaging、共享 Connector 和 Codex 缓存。不同目录不能实现两套正式安装并存验收；测试请使用干净或可回滚的专用 Mac/VM。Mac 注册元数据仍按浏览器要求位于用户 Library，浏览器扩展本体位于所选可见目录。

## 卸载与凭据

从当前安装包根运行“卸载.command”。只有当前根有匹配运行配置，或用户显式指定并核对目标，才处理本次受管运行副本及其注册。未安装的新解压包会提示“此目录未安装，未删除”，不会自动转向其他已安装目录。扩展源码、用户文件、共享缓存、系统 Python、天源 CLI 保留；Chrome 中的扩展由用户手动移除。

MCP token、账号、密码、验证码和管理员密码只能由用户本人输入，不交给 Agent、不写入报告。业务验证使用工作副本；包校验和脚本静态检查不能替代 Mac 实际安装和浏览器目录选择验收。
