## 结论

ego 可以通过脚本控制浏览器完成天源资产基础法“评估核实”阶段的分类附件上传。

本次在 `其他应付款` 科目验证的链路如下：

1. 打开资产基础法底稿页面。
2. 切换到评估核实阶段。
3. 通过 SpreadJS 对象定位当前 sheet 和“查证资料索引”列。
4. 调用自定义 cellType 的 `activateEditor(true, ...)` 打开分类上传弹窗。
5. 使用 ego 的 `uploadFile` 注入本地 PDF。
6. 点击弹窗“保存”触发真实上传接口。
7. 系统返回附件 ID 和分类批次号。

## 关键规则

1. 不要按固定列号写死。不同科目的评估核实列布局会变，必须读取表头自动寻找“查证资料索引”列。
2. 不要再走“注释文件”入口。评估核实阶段上传资料的位置是“查证资料索引”字段，不是 `ZSWJ` 注释文件。
3. 不要把单击、双击、F2 作为唯一方案。SpreadJS 自定义上传单元格更稳的入口是 cellType 的 `activateEditor(true, null, null, { sheet, row, col })`。
4. 行列索引要区分：用户看到的 `P2` 在脚本中是 `row = 1, col = 15`，即 0 基索引。
5. 上传弹窗里 `el-upload` 是 `auto-upload=false`。只调用 `uploadFile` 只能让文件在前端回显；必须触发弹窗自己的“保存”逻辑，才会先调用 `/ty/api/attach/upload`，再调用 `/ty/api/assignment_draft/cell_file/classify_upload`。
6. 正式落库还需要 `/ty/api/assignment_draft/save` 成功。若存在编辑锁，附件可上传、分类批次可生成，但底稿字段不会正式保存。
7. 默认不能绕过只读/编辑锁。前端只读绕过只能用于“验证浏览器上传能力”的临时测试，不能作为正式业务上传策略。
8. 每次测试后必须回读明细接口，确认目标字段是否落库；不能只看页面显示。
9. 测试文件应使用小体积、可识别的占位 PDF，并在日志中记录是否保存、是否清理。
10. 输出必须包括：目标项目/主体/科目/行号、目标字段、文件路径、接口返回、保存结果、回读结果、是否污染正式底稿。

## 后续 skill 化建议

建议 skill 名称：`tianyuan-ego-attachment-upload`

建议输入参数：

- `projectId`
- `companyId`
- `subjectCode`
- `valuationType`，资产基础法当前使用 `1`
- `draftDataType`，评估核实当前使用 `1`
- `rowNumber`，用户视角行号，如 `2`
- `fieldTitle`，默认 `查证资料索引`
- `filePath`
- `moduleName` 或 `moduleIndex`，如 `凭证`、`合同`、`期后支付`
- `saveMode`：`dry_run` / `upload_only` / `save`

建议完成门禁：

- 能打开目标底稿。
- 能识别当前 sheet 和目标列。
- 能打开目标单元格上传弹窗。
- 能注入文件并看到前端文件名。
- 能观察到 `/ty/api/attach/upload` 成功。
- 能观察到 `/ty/api/assignment_draft/cell_file/classify_upload` 成功。
- 若 `saveMode=save`，必须观察到 `/ty/api/assignment_draft/save` 业务成功。
- 必须回读目标行字段，确认与批次号一致。
