# 微信与企业微信文件归档第二阶段决策

## 目标

在第一阶段下载监听、稳定判断、复制校验和未知来源保护的基础上，增加会话清单、搜索、多选、目录绑定和来源匹配接口。

## 实现

- 新增 `native-helper/file-archive-conversations.js`，作为微信和企业微信适配器的统一边界。
- 侧栏增加“加载会话”、搜索、全选当前结果、清空选择和“选择目录并绑定”。
- 绑定只保存会话 ID、显示名称、会话类型和用户选择的导出目录。
- 来源索引只接受精确绝对文件路径与会话 ID；存在已确认绑定时才返回 `high` 置信度。
- 未绑定或无法精确匹配的文件继续进入 `来源未知待确认`，不会按文件名、群名称或时间猜测来源。

## 当前本机结论

2026-08-04 检查发现：

- 微信 `db_storage/contact`、`session`、`message` 数据库文件不是标准 SQLite 文件头，属于加密或专有格式。
- 企业微信 `Profiles/.../Contact`、`Messages1`、`roster.db` 同样不是标准 SQLite 文件头。
- 当前不尝试解密、不读取聊天正文、不注入进程、不修改客户端包。
- 因此本机接口会返回“会话数据库已加密，暂时无法可靠加载联系人和群聊”，不会伪造会话清单。

## 后续接入门槛

只有发现官方或稳定的本地非正文接口，且能把文件下载路径精确关联到会话 ID，才开放真实会话列表和高置信度自动归档。否则保持当前不可用提示与未知来源待确认模式。
