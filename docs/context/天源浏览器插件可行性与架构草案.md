# 天源浏览器插件可行性与架构草案

记录时间：2026-07-22

## 一、结论

可以开发，技术可行性较高。

建议把它定位为“天源系统浏览器工作台”，由浏览器插件负责页面识别、操作执行、结果回读和留痕；现有 Tianyuan skills 负责业务规则、参数组织和完成门禁。

已验证的基础能力：

| 能力 | 当前状态 | 可迁移内容 |
|---|---|---|
| 识别项目、主体、科目和底稿页面 | 已验证 | URL、页面标题、SpreadJS sheet |
| 自动定位评估核实字段 | 已验证 | 按表头查找，不写死列号 |
| 打开分类附件上传弹窗 | 已验证 | `operation-upload-cell.activateEditor(true, ...)` |
| 上传本地文件 | 已验证 | `input[type=file]`、真实附件接口 |
| 生成分类附件批次 | 已验证 | `/assignment_draft/cell_file/classify_upload` |
| 保存资产基础法底稿 | 已有 skill 和脚本 | `tianyuan-asset-draft-save` |
| 检查编辑锁 | 已验证 | 页面状态及 `/assignment_draft/save` 返回 |
| 保存后接口回读 | 已验证 | 底稿明细、汇总表回读 |

## 二、推荐架构

```text
浏览器插件侧边栏
  |
  | 任务参数、确认、进度、结果
  v
扩展后台 Service Worker
  |
  | 消息协议
  v
Content Script
  |
  | 注入 MAIN world
  v
天源页面适配器
  |- 页面/项目/主体/科目识别
  |- SpreadJS 表格控制
  |- 附件上传
  |- 底稿保存
  |- 编辑锁检查
  |- 接口回读
  `- 操作证据采集

可选本地助手
  |- 批量读取指定目录文件
  |- 文件路径与行号映射
  `- 向插件安全传递文件内容
```

### 1. 插件侧边栏

建议使用 Chrome Manifest V3 Side Panel，展示：

- 当前项目、主体、科目、阶段、sheet。
- 当前选择行、关键字段和附件状态。
- 单文件上传、批量上传、保存当前科目、批量保存科目。
- 执行模式：检查、预演、正式执行。
- 编辑锁、接口状态、回读结果、异常信息。
- 本次操作日志和可导出的 JSON 证据。

### 2. 页面世界适配器

浏览器 content script 处于隔离环境，不能直接稳定访问页面中的 `GC.Spread.Sheets`。应注入页面 MAIN world，并通过 `window.postMessage` 或自定义事件与 content script 通信。

页面适配器应只依赖相对稳定的信号：

- URL 路由。
- 表头文字和字段编码。
- cellType 的 `domId=operation-upload-cell`。
- 页面按钮文字。
- 已验证的天源接口返回。

不要依赖：

- 固定坐标。
- 固定列号。
- 压缩后的类名、函数名或 Vue 内部 UID。
- 单次截图推断。

### 3. 本地文件访问

浏览器扩展不能无条件读取任意本地路径。

第一阶段可使用：

- 用户在插件中选择文件或目录。
- File System Access API 保存用户授权后的目录句柄。

需要无人值守批量上传时，再增加：

- Chrome Native Messaging 本地助手；或
- 本机 localhost 服务，仅监听 `127.0.0.1`，使用随机会话密钥。

本地助手只负责文件读取和任务队列，不保存天源账号、Cookie 或 token。

## 三、功能模块

### A. 页面上下文

- 获取 `projectId`、`companyId`、`subjectCode`。
- 识别当前阶段。
- 读取当前 sheet、活动行和表头。
- 校验当前页面是否属于目标项目和主体。

### B. 资产基础法附件上传

- 按字段标题寻找“查证资料索引”。
- 读取目标行 `_id` 和现有 `CZZLSY`。
- 调用上传 cellType 打开分类弹窗。
- 按分类名称选择“凭证、合同、期后支付、其他”等上传区域。
- 注入文件并触发弹窗保存。
- 监听附件上传、分类批次和底稿保存请求。
- 回读目标行确认批次号落库。

### C. 资产基础法底稿保存

迁移现有 `tianyuan-asset-draft-save` 的能力：

- 保存当前科目。
- 按 subjectCode 批量保存。
- 可选“选择更多 -> 全选 -> 确定”。
- 识别登录失效、按钮缺失、编辑锁和保存失败。
- 保存后刷新并回读资产基础法汇总。

### D. 安全门禁

- 默认使用“预演”模式，只识别和展示，不写入。
- 正式执行前展示项目、主体、科目、行、字段、文件和分类。
- 编辑锁不属于当前用户时停止，不能绕过。
- 只看到前端文件名不算成功。
- `/attach/upload` 成功只代表附件入库。
- `/cell_file/classify_upload` 成功只代表分类批次生成。
- `/assignment_draft/save` 成功且明细回读一致，才算底稿保存完成。

### E. 操作日志

每次任务记录：

- 时间、当前用户、项目、主体、科目、阶段。
- 目标行、字段、分类和文件名。
- 原字段值和新字段值。
- 请求端点、业务 code、requestId。
- 编辑锁状态。
- 页面回显和接口回读。
- 成功、部分成功、失败、已回滚。

日志不得记录 Cookie、Authorization、密码、验证码和完整 token。

## 四、插件与 Skill 的关系

浏览器插件不应替代 skill。

- Skill：定义“为什么做、做哪些科目、参数如何确定、成功标准是什么”。
- 插件：定义“如何在天源页面安全、稳定地执行和回读”。

建议形成统一动作协议：

```json
{
  "action": "upload_asset_check_attachment",
  "projectId": "165353602809858",
  "companyId": "165353602809933",
  "subjectCode": "C5-10-3",
  "rowNumber": 2,
  "fieldTitle": "查证资料索引",
  "moduleName": "凭证",
  "fileName": "ego_upload_test.pdf",
  "mode": "dry_run"
}
```

后续 Codex skill、CLI、本地助手和插件侧边栏都使用同一动作协议，避免各写一套页面逻辑。

## 五、开发阶段

### 第一阶段：MVP

- 仅支持 `excel.zhrdc.net/ty/*`。
- 自动识别当前资产基础法底稿。
- 显示项目、主体、科目、阶段和编辑锁。
- 保存当前科目。
- 对当前行上传一个附件。
- 执行后回读并输出日志。

### 第二阶段：批量任务

- 按科目列表批量保存。
- 按“行号/对象名称/底稿行 ID”匹配附件。
- 支持一个目录内多文件映射。
- 提供失败重试，但不自动绕过编辑锁。

### 第三阶段：Skill 接入

- 封装 `tianyuan-browser-control` 执行层。
- 将 `tianyuan-asset-draft-save` 改为调用统一动作协议。
- 新建 `tianyuan-asset-check-attachment-upload` skill。
- 将执行证据回传给 Codex，并写入项目日志。

### 第四阶段：扩展其他功能

- 科目通用文件。
- 注释文件和其他底稿附件。
- 批量导入后的保存和汇总刷新。
- 数据一致性检查和差异清单。
- 项目文件下载、归档和附件证据索引。

## 六、主要风险

1. 天源前端版本更新可能改变组件结构，需要适配器版本检测和回归测试。
2. SpreadJS 和 Vue 运行在页面世界，扩展必须设计稳定的 MAIN-world 消息桥。
3. 浏览器本地文件访问受安全限制，批量自动化可能需要本地助手。
4. 编辑锁必须作为硬门禁，不能通过前端改只读状态进行正式保存。
5. 上传成功和底稿保存成功是两个状态，UI 必须明确区分。
6. 页面使用当前登录态执行，插件不能自行存储或导出账号凭据。

## 七、建议

建议先开发一个 Chrome Manifest V3 原型，第一版只做两个已验证动作：

1. 保存当前资产基础法科目。
2. 在评估核实阶段向当前行“查证资料索引”上传附件并回读。

这两个动作跑稳后，再增加批量目录、任务队列和 Skill 接入。原型验证完成后，应从具体评估项目目录迁移到独立代码仓库。
