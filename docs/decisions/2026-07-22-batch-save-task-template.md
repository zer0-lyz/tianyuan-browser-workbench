# 任务模板决策：批量保存底稿

日期：2026-07-22

## 结论

将“批量保存底稿”作为天源浏览器工作台的第一个任务模板接入侧边栏。后续附件上传、批量导出、回读核验等功能沿用同一模式：任务参数、预演、执行、证据 JSON。

## 范围

本模板支持：

- 科目：从当前页面左侧科目树和当前底稿读取，加载到插件面板，用复选清单选择，不要求手工输入代码。
- 公司范围：当前公司、部分公司、全部公司；部分公司从天源“选择更多”弹窗读取公司清单，加载到插件面板多选。
- 执行方式：预演、不点击保存；正式执行、点击保存。

## 设计

- 侧边栏负责任务编排：读取当前页面上下文、按科目代码切换底稿 URL、逐个发起保存动作。
- 页面适配器负责页面内动作：确认底稿页、选择公司范围、点击保存、捕获页面消息和保存后上下文。
- 公司清单通过点击页面 `选择更多` 弹窗读取，读取后关闭弹窗，不点击 `确定`；选择发生在插件面板中。
- 科目如果有 `subjectCode`，批量时按 URL 打开；如果只有左侧树名称，批量时按名称点击左侧树切换。
- `全部公司` 和 `部分公司` 通过页面中的 `选择更多`、`全选`、`确定` 等文字按钮操作，不使用坐标。
- 多科目循环时，每个科目重新打开 URL 并重新选择公司范围，符合 `tianyuan-asset-draft-save` skill 中“页面 reload 后公司主体选择会重置”的经验。

## 门禁

- 默认是 `dry_run`，只定位页面和保存按钮，不点击保存。
- 正式执行必须选择“正式执行，点击保存”，并勾选确认。
- 若当前页不是资产基础法底稿页、登录疑似失效、保存按钮不可见，则停止。
- 当前版本不保存 Cookie、Authorization、密码、验证码或 token。
- 当前版本不上传文件。

## 已知限制

- `部分公司` 的选择依赖天源弹窗中公司编号、简称或名称可见；若弹窗结构变化，任务会停止并返回弹窗文本。
- “显示科目”清单当前优先来自 URL 当前 subjectCode 和页面可见 subjectCode；若天源隐藏更多科目但页面未暴露，需要后续增加专门的科目选择弹窗读取器。
- 插件内只能确认页面是否出现 `保存成功` 等前端证据；最终仍应通过天源汇总/明细接口或既有 skill 做保存后回读核验。
- 尚未完成真实“点击保存”执行验证。
